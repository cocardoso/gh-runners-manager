# M3 — Real-Time Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the web UI described in spec §11, built with React and Kumo, embedded in the `ghrm` binary, and updating in real time from the M2 API (REST + SSE). It covers overview, jobs, environments, scale sets, live logs and a read-only settings page. Templates get a placeholder page until M4.

**Architecture:**
- `web/` is a Vite + React 19 + TypeScript application, styled with Tailwind CSS v4 and `@cloudflare/kumo`, and routed with TanStack Router.
- Server state comes from TanStack Query, through a typed client generated from the API's OpenAPI document (`openapi-typescript` + `openapi-fetch`).
- One shared `EventSource` on `/api/v1/events/stream` invalidates queries as events arrive.
- Log views open their own SSE stream and render with TanStack Virtual.
- The built assets are embedded with `go:embed` and served by `internal/api` for every non-API path, with an SPA fallback.
- `ghrm demo` runs the real API with a fake runtime and a simulated scale set, for UI development and browser tests without Proxmox or GitHub.

**Tech Stack:** React 19, Vite, TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`), `@cloudflare/kumo` 2.x (with `@phosphor-icons/react`, `echarts`, `zod` peers), TanStack Router, TanStack Query, TanStack Virtual, `openapi-typescript`, `openapi-fetch`, Vitest and Testing Library, Playwright. pnpm.

**Spec:** `docs/superpowers/specs/2026-10-07-gh-runners-manager-design.md` §11

## Global Constraints

- All earlier Global Constraints apply: English only, no Claude attribution, `CGO_ENABLED=0` for Go.
- `docs/architecture.md` is updated in the same change as UI architecture.
- `go build ./...` must keep working without Node.js. The embed falls back to a page that explains how to build the UI.
- The UI follows the Cloudflare dashboard patterns of spec §11.1:
  - sidebar, breadcrumbs, `page-header`, `resource-list` with `table`, `toolbar` and `pagination`;
  - `tabs` on detail pages;
  - `command-palette` (⌘K);
  - a Live indicator;
  - light and dark themes from Kumo tokens.
- Kumo components are used wherever Kumo has one. Documentation comes from `npx @cloudflare/kumo doc <Component>`.
- No mutating UI actions except "Destroy environment", which asks for the admin token (stored in `sessionStorage`) until M5 adds sign-in.

## Review Focus

1. **SSE disconnects** (control-plane restart, network blip). The UI must reconnect, resume from the last event ID, and show the Live indicator as reconnecting, never as silently stale.
2. **High-volume logs** (tens of thousands of lines). The log viewer must stay responsive, must not grow memory without bound (cap with "load earlier"), and must keep the scroll position while the operator reads.
3. **Unknown or newer enum values from the API** (a new state or event kind). They must render as a neutral badge, never crash.
4. **Empty states and a fresh install** (no jobs yet). Every page shows guidance, not a blank table.
5. **Long names and narrow screens.** Repository, workflow and job names truncate with tooltips, and tables scroll horizontally on phones.

### Task 1: API additions for the UI

Endpoints (huma, typed):
- `GET /api/v1/overview`:
  - KPIs: running jobs, waiting demand, jobs in the last 24 h, success rate over 24 h, median time from queued to started over 24 h;
  - capacity: environments live and max, memory committed and budget, host memory available, disk percent;
  - alerts: listener errors, recent failed environments.
- `GET /api/v1/stats/jobs?hours=24`: per-hour counts by result.
- `GET /api/v1/settings`: sanitized configuration (no secrets) and the version.
- `GET /api/v1/jobs/{id}/github`: the step list and URL from the GitHub REST API (`/repos/{owner}/{repo}/actions/runs/{run_id}/jobs`, matched by runner name). When the credential lacks **Actions: read**, it answers 200 with `{"available": false, "reason": "..."}` so the UI can explain what to change.

Tests: handler tests with a seeded store. For the GitHub endpoint, a fake HTTP server covering three cases: steps found, 403 (`available=false`) and job not found.

### Task 2: `ghrm demo`

`cmd/ghrm/demo.go` and `internal/demo`. It serves the real API with:
- a temporary store;
- `runtimetest.Fake`;
- a simulated GitHub that, every few seconds, assigns jobs to two scale sets;
- a simulated agent that drives environments through the full lifecycle, writes `runner`/`job`/`metrics` log lines (including ANSI colour and occasional failures), and exercises every state.

Flags: `--listen`, `--seed`, `--speed`.

Test: running the demo for N simulated cycles leaves no live environments behind and produces events of every kind.

### Task 3: Web scaffold, build and embed

- `web/`: pnpm, Vite, React, TypeScript (strict), Tailwind v4 with the Kumo `@source`/`@import` order from Kumo's README, TanStack Router and Query, ESLint, Vitest.
- `web/embed.go`: `//go:embed all:dist` with a `dist/.keep` committed. `internal/api` serves the UI for non-API paths, with an SPA fallback to `index.html` and long cache headers for hashed assets.
- `make web` (`pnpm install --frozen-lockfile && pnpm build`), `make web-api` (regenerate `web/src/api/schema.d.ts` from `ghrm openapi`, a new subcommand that prints the OpenAPI document).
- CI: a `web` job (lint, typecheck, unit tests, build); the Go build job builds the UI first.

Tests: the Go test for UI serving checks the SPA fallback, that API paths are untouched, and the cache headers.

### Task 4: App shell

Kumo `sidebar` (Overview, Jobs, Environments, Scale sets, Templates, Live logs, Settings), `breadcrumbs`, `page-header` per page, `command-palette` (⌘K) searching jobs, environments, scale sets and commit SHAs, theme toggle, a Live indicator bound to the shared SSE connection state, and `toast` for action results.

Tests (Vitest): navigation renders each route; the palette finds an item; the Live indicator reflects `connecting`/`live`/`reconnecting`.

### Task 5: Real-time data layer

- `useEventStream()`: one `EventSource` with exponential reconnect, resuming with the last sequence (`?after=`). It dispatches events to query invalidation by kind and exposes the connection state.
- `useLogStream(envId, stream)`:
  - loads a backlog page, then follows with SSE (`follow=true`, resuming from the last offset);
  - caps memory at 50k lines, with a "load earlier" control.
- Unknown kinds or states are passed through untyped (Review Focus #3).

Tests: a fake `EventSource` covering reconnect and resume, lag, unknown kinds, and the line cap.

### Task 6: Overview page

- KPI cards.
- Capacity `meter`s.
- A jobs-per-hour `chart` (Kumo chart on ECharts).
- A live "Now" list of active environments, linked.
- Alert `banner`s.
- Empty state for a fresh install (Review Focus #4).

### Task 7: Jobs list and job detail

- **List:**
  - a `resource-list` table with live updates, filters (scale set, status, repository) and search;
  - truncated names with tooltips (Review Focus #5);
  - pagination.
- **Detail** `tabs`:
  - **Timeline:** lifecycle stages with durations, failed stage highlighted. Kumo `flow` if it fits, otherwise a small component on Kumo tokens.
  - **Steps:** from `/jobs/{id}/github`, or an explanation of the missing permission.
  - **Logs:** the log viewer with stream selector, pause/resume, search, wrap, copy and download.
  - **Resources:** CPU/memory chart from the `metrics` stream.
  - **Environment:** runtime details.

### Task 8: Log viewer component

A virtualized viewer (TanStack Virtual) styled like Kumo `code`:
- ANSI SGR colours;
- follow mode that pauses when the user scrolls up and resumes with "jump to latest";
- search with highlight;
- line numbers and timestamps toggle;
- copy and download.

Tests: render 50k lines without timing out; ANSI parsing; follow/pause behaviour.

### Task 9: Environments, scale sets, live logs, settings, templates placeholder

- **Environments:** list and detail (same tabs as the job, without Steps); the destroy action uses the `delete-resource` block plus the admin-token prompt.
- **Scale sets:** cards with listener status, desired and live counts, the waiting reason, and a `runs-on` snippet with `clipboard-text`.
- **Live logs:** the global event stream with filters (level, kind, scale set, environment), pause/resume, and a cap with "load earlier".
- **Settings:** a read-only view of `/api/v1/settings`.
- **Templates:** a placeholder explaining M4.

### Task 10: Browser tests and visual check

Playwright against `ghrm demo` covers:
- every page renders with no console errors;
- a job progresses live without a reload;
- following a log appends lines;
- an SSE disconnect and reconnect (restart the demo) resumes (Review Focus #1);
- a phone viewport has no horizontal page scroll except inside tables (Review Focus #5).

Screenshots of each page, light and dark, are saved under `docs/images/` and linked from the README.
